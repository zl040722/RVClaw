# K1 复现指南

## 硬件与系统

基线为 SpacemiT K1/MUSE Pi Pro（八核 RISC-V）、V550 ROS2 底盘及 C30D STM32 控制器、M10 雷达、讯飞 M260C、USB 音箱、Astra Pro RGB 摄像头。已有合适的底盘固件可保留，无需重新刷写。

板端使用 Bianbu、系统 Python **3.12**、ROS2 Humble 和 SpacemiT OpenCV/ONNX Runtime。`deploy/k1/snapshot/system-packages.json` 记录相关包版本；`python-packages.json` 用于比对，不应整份覆盖安装。

工程放在 `/data/RVClaw`，SDK 放在 `/data/spacemit_robot`。先按 SpacemiT 官方说明安装对应 K1 系统及 ROS2。`robot/vendor/spacemit_robot` 包含本项目实际构建用到的 SDK 源码、build/scripts/target 入口及本工程修改；`deploy/k1/snapshot/sdk-sources.json` 固定来源修订。源码不能替代基础系统镜像和板厂系统包。

## 1. 源码与资源

```bash
git clone https://github.com/zl040722/RVClaw.git /data/RVClaw
cd /data/RVClaw
# PR 合入前执行以下三行；合入后直接使用 main，跳过这三行。
git remote add k1-delivery https://github.com/jxgxxx/RVClaw-K1.git
git fetch k1-delivery codex/k1-reproducible-source
git switch --detach k1-delivery/codex/k1-reproducible-source
python3 scripts/check_delivery.py
# 从 models/README.md 的配套资源预发布下载两个包后，再执行导入。
python3 scripts/import_k1_assets.py \
  --portable-archive /path/to/assets.tar.gz \
  --vision-archive /path/to/vision-models.tar.gz
python3 scripts/check_delivery.py --require-assets
```

资源交付状态及清单见 `models/README.md`。缺少资源包时无法完整运行推理/原音色播报。导入器先核对全部成员、大小及 SHA256，再导入；拒绝路径越界、链接及覆盖不同的已有资源。

## 2. 依赖与组装

底层驱动、厂商运行库和 TCM 设备权限的对应关系见 [K1 驱动与支撑模块](K1-驱动与支撑模块.md)。系统基线为 Bianbu 2.3.5 / riscv64、内核软件包 6.6.63-2.2.9.2；版本和软件源元数据见 `deploy/k1/snapshot/support-stack.json`。项目源码不包含 Linux 全量源码或模块内部厂商固件。

新 K1 除下文依赖外，还需匹配的 `spacemit-tcm=3.0.0-bpo1+2` 和 `spacemit-modules-usrload=0.1.3`，按同系统的正式板厂软件源准备。`deploy/k1/udev/80-rvclaw-tcm.rules` 由第 4 节通配符安装步骤一并安装；不要遗漏 `/dev/tcm` 的 `video` 组访问权限。

通过对应 Bianbu/板厂软件源准备 `build-essential`、`cmake`、`ninja-build`、`git`、`python3-dev`、`python3-pip`、`python3-numpy`、`python3-yaml`、`python3-serial`、`python3-requests`、`python3-pil`、`python3-colcon-common-extensions`、`python3-pybind11`、`alsa-utils`、`v4l-utils`、`libasound2-dev`、`libeigen3-dev`、`libyaml-cpp-dev`、`libpcap-dev`、`libpcl-dev`、`libportaudio2`，以及 `ros-humble-navigation2`、`ros-humble-nav2-bringup`、`ros-humble-slam-toolbox`、`ros-humble-robot-localization`、`opencv-spacemit`、`spacemit-onnxruntime`、`python3-spacemit-ort`。以版本清单和板厂源实际包名为准，不使用 x86 二进制。

音频/ASR 原生编译还需 `pkg-config`、`portaudio19-dev`、`libsndfile1-dev`、`libsamplerate0-dev`、`libcurl4-openssl-dev`、`libfftw3-dev`；SDK 各组件的 `package.xml` 同时记录系统依赖。按本指南先装齐，因为构建入口设置 `AUTO_INSTALL_DEPS=no`，不会在编译时自动安装系统包。

```bash
export SROBOTIS_ROOT=/data/spacemit_robot
# 首次准备独立 SDK 目录；已有 SDK 先比对版本，勿覆盖正在运行的设备。
mkdir -p "$SROBOTIS_ROOT"
cp -a robot/vendor/spacemit_robot/. "$SROBOTIS_ROOT/"
test -d "$SROBOTIS_ROOT/build"
test -d "$SROBOTIS_ROOT/components"
test -d "$SROBOTIS_ROOT/application"
test -d "$SROBOTIS_ROOT/target"

# 填写该 K1 当前实际拥有的 LAN 或 Tailscale IPv4 地址。
python3 deploy/k1/assemble_snapshot.py --bind-address <K1地址>
bash deploy/k1/prepare_ros_middleware.sh
bash deploy/k1/prepare_compiler.sh
bash deploy/k1/build_workspaces.sh
bash deploy/k1/build_native.sh
gcc -O3 -ffp-contract=off -fPIC -shared \
  deploy/k1/compatibility/scan_map_kernel.c \
  -o deploy/k1/compatibility/scan_map_kernel.so -lm
bash deploy/k1/native/amcl/build_amcl.sh /data/RVClaw/build/k1/amcl
install -D -m 755 build/k1/amcl/libamcl_core.so runtime/k1/native/amcl/libamcl_core.so
```

组装仅用于新 checkout，已有 `runtime/k1` 时拒绝覆盖。`--source-only` 用于离线核对组装关系，不代表可运行部署。原生编译在 K1 进行；NCNN 使用 GCC 14、保留 RVV 并关闭不兼容半精度路径。

AMCL 要求与当前 `ros-humble-nav2-amcl 1.1.18` 头文件/库的 ABI 匹配，见 `deploy/k1/native/amcl/README.md`。工程动态库不覆盖系统 ROS。

## 3. 构建网页

在开发电脑使用 Node.js 22.12+ 和 pnpm：

```bash
cd studio/web-vue
pnpm install --frozen-lockfile
pnpm run build
```

将生成的 `studio/web` 同步到板端同名目录；K1 不运行 Node 开发服务器。开发代理地址在 `vite.config.js` 配置，生产页面使用当前网站来源。构建输出不重复提交到 Git。

## 4. 权限与服务安装

```bash
sudo install -m 644 deploy/k1/udev/*.rules /etc/udev/rules.d/
sudo udevadm control --reload-rules
sudo udevadm trigger
sudo usermod -aG dialout,audio,video "$USER"
sudo install -d -o "$(id -u)" -g "$(id -g)" /data/inspection_photos
sudo loginctl enable-linger "$USER"
sudo bash deploy/k1/install_control_priority.sh
sudo bash deploy/k1/install_depth_permissions.sh
```

现场基线登录用户为 `firefly`，现有优先级 sudoers 按该用户限制；使用其他用户名时先调整 `deploy/k1/sudoers/rvclaw-control-priority` 与安装脚本的用户检查。可选的语音模块内部恢复使用系统 `adb` 和 `acl` 包；安装后按需执行 `sudo bash deploy/k1/enable_voice_diagnostics.sh` 授权当前模块的调试接口。USB 重新连接后临时调试权限失效，但正常串口/音频识别不依赖调试权限。

重新登录以获得新增用户组。设备 USB 标识不同的同型号硬件需调整 udev/设备配置；无需更改导航算法。`start_runtime.sh --check` 检查底盘、雷达、语音、相机、音箱及构建文件。

```bash
python3 deploy/k1/install_snapshot.py --bind-address <K1地址>
python3 deploy/k1/install_snapshot.py --bind-address <K1地址> --install
bash deploy/k1/start_runtime.sh --check
```

安装器默认仅检查，`--install` 才写用户级 systemd 配置。它不启用/启动服务，不发运动指令；存在同名服务或 drop-in 时拒绝覆盖。

## 5. 启动与使用

```bash
bash deploy/k1/start_runtime.sh --start
systemctl --user enable --now rvclaw-inspection-control.service \
  rvclaw-inspection-progress.service rvclaw-studio.service rvclaw-studio-voice-health.service
systemctl --user status rvclaw-vendor-command rvclaw-resource-scheduler \
  rvclaw-meter-gauge rvclaw-camera-api rvclaw-studio
```

启动服务不会下达巡检运动。打开 `http://<K1地址>:8017/`。内部相机 API 占用 `127.0.0.1:8017`，网页绑定另一实际地址，控制接口为该实际地址的 `8019`。网页不要绑定 `127.0.0.1` 或 `0.0.0.0`，避免端口冲突。

原场地沿用已保存地图和 A→B→C→ORIGIN 配置，起点和朝向需与地图一致；其他场地先重新建图并配置点位/阈值。就位后用网页或“小薇小薇”→“开始巡检”启动。

云端是可选项。按 `services/meter_gauge/CLOUD_METER.md` 使用自己的 API 密钥并限制文件权限，密钥不随代码提供。首次本地失败后并行云端的策略保留，可用性取决于自己的云端服务/网络。Astra RGB 用于识别，深度流不是已完成的复现能力。

```bash
journalctl --user -u rvclaw-vendor-command -u rvclaw-nav2-persistent -f
```

已知边界见 `docs/交付说明.md`。无运动组装/构建检查不能代替另一台全新 K1 的实地验收。
