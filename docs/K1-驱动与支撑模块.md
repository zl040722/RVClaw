# K1 驱动与支撑模块

## 交付边界

本项目的可复现交付由项目源码、设备配置、板厂基础系统/运行库、模型/语音资源共同组成。源码包含底盘固件、ROS2 驱动、设备适配和所需 SDK 模块，不等于把 Linux 与所有厂商运行库都从源码交付。

2026-11-06 实机只读核查基线为 Bianbu **2.3.5 / riscv64**，内核 **6.6.63，软件包 6.6.63-2.2.9.2**。详细版本、来源与已发布软件包的元数据哈希见 `deploy/k1/snapshot/support-stack.json`。已核对三个串口接口实际绑定 `cdc_acm`，RGB 绑定 `uvcvideo`，麦克风/音箱接口绑定 `snd-usb-audio`。

## 代码和系统驱动对应关系

| 能力 | 项目交付内容 | 系统/厂商部分 |
| --- | --- | --- |
| 电机、编码器、IMU、手柄、底盘状态 | `robot/firmware/c30d-v8.1` 固件源工程 | STM32/Keil 工具链按厂家板型准备；已有匹配固件不必重刷 |
| 上位机底盘控制、遥测、里程计 | `robot/ros2_ws/src/rvclaw_stm32_base`，实际任务覆盖层在 `deploy/k1/compatibility` | 当前 USB 串口由内核 `cdc_acm` 提供 |
| M10 雷达数据和 ROS2 消息 | `lslidar_driver` 5.1.1 与 `lslidar_msgs` | 同样使用 `cdc_acm`，命名规则为 `deploy/k1/udev/99-rvclaw-m10.rules` |
| Astra Pro RGB 画面 | `services/rvclaw_api/native`，RGB 辅助代码和配置 | 内核内置 UVC、V4L2、SpacemiT OpenCV；不依赖 Astra 深度插件 |
| M260C 唤醒/串口交互、主机识别和播放 | `services/rvclaw_voice`，设备规则、ALSA 配置、ASR/VAD SDK 源码 | 内核 USB Audio、串口驱动；模块内部唤醒程序/固件由厂商预装 |
| 本地识别和图像处理 | `robot/vendor/spacemit_robot`，`robot/vendor/native`，`services/*/native` | `spacemit-onnxruntime`、`python3-spacemit-ort`、`opencv-spacemit`、`spacemit-tcm` |
| TCM 设备访问 | `deploy/k1/udev/80-rvclaw-tcm.rules`，已有按需清理脚本 | `CONFIG_SPACEMIT_TCM=y` 内置内核接口与板厂用户态库 |
| 导航/建图/定位 | 工程 ROS2 源码、K1 覆盖层、AMCL 源码和扫描匹配内核 | ROS2/Nav2/slam_toolbox/robot_localization 对应版本软件包 |
| Wi-Fi、USB 控制器和平台基础设施 | 无项目新增驱动补丁 | K1 系统镜像/内核提供；实机 Wi-Fi 使用 `8852bs` |
| Astra Pro 深度 | 已有可选读流接口和权限配置 | 当前未取得并验证可用的 RISC-V Astra Pro 设备驱动；不作为正常巡检必需项 |

本机 `CONFIG_USB_ACM=m`，UVC、USB Audio、TCM 为内置驱动。不要因为内置驱动不出现在 `lsmod` 中就判断缺失。厂家资料中的 CH343 Linux 驱动仅在设备和系统确实需要时考虑；目前三路串口都已由 `cdc_acm` 驱动，无需另装 CH343 模块。

## 板厂基础包

保留匹配的 K1 Bianbu 系统，按该系统正式软件源安装依赖。以下是当前已安装版本，不能用 x86/ARM 的同名库替代：

| 软件包 | 版本 | 用途 |
| --- | --- | --- |
| `linux-image-6.6.63` | `6.6.63-2.2.9.2` | 内核及设备驱动基线 |
| `spacemit-modules-usrload` | `0.1.3` | 板厂平台模块加载流程，系统内已有对应服务 |
| `spacemit-tcm` | `3.0.0-bpo1+2` | TCM 用户态库、头文件及管理工具 |
| `spacemit-onnxruntime` | `2.0.3-bpo1` | 原生 ONNX Runtime 与 SpacemiT 执行库 |
| `python3-spacemit-ort` | `2.0.3-bpo1` | 对应 Python 绑定；包版本不同于 Python 模块报告的 ORT 引擎版本 |
| `opencv-spacemit` | `4.14.0-1bb3` | 当前图像处理与编解码依赖 |

来源为 `archive.spacemit.com/bianbu` 的 Bianbu v2.3 对应仓库。不要把跨版本软件源配置整份覆盖到其他系统；应先比对板型/系统，再按官方软件源配置取得固定包。包内 copyright 信息不足以证明所有厂商修改均可重新分发为源码，因此本项目记录来源和版本，不把这些已安装 `.so` 当作自研源码提交。

```bash
# 查看当前系统与软件源候选，无安装操作。
cat /etc/os-release
uname -r
apt-cache policy spacemit-tcm spacemit-modules-usrload \
  spacemit-onnxruntime python3-spacemit-ort opencv-spacemit

# 新 K1：先准备匹配的正式软件源，再按实际缺项安装；不在运行任务期间换包。
sudo apt-get install spacemit-tcm=3.0.0-bpo1+2 spacemit-modules-usrload=0.1.3 \
  spacemit-onnxruntime=2.0.3-bpo1 python3-spacemit-ort=2.0.3-bpo1 \
  opencv-spacemit=4.14.0-1bb3
```

清单内包 SHA256 是实机 APT 元数据的记录，本次没有重新下载/安装这些 `.deb`。后续包若从软件源移除，需要维护可用的官方来源或经授权的附件，不能保证软件源永久保留旧版本。没有在本次整理中复制系统库或替换系统内核。

## TCM 权限补充

实机 `/dev/tcm` 为 `root:video`、`0660`；现场用户属于 `video` 组。`80-rvclaw-tcm.rules` 将这一规则纳入工程，避免新设备只装了应用程序却没有权限访问处理链所需接口。它不改变推理策略、CPU 分配或运动控制。

实机原规则 SHA256：`6d8df0a76c5c7a4ebdf21e2a4374ee33945c291e764ea3cff73eab60a2f6e42b`。原复现指南安装 `deploy/k1/udev/*.rules` 的命令会同时包含此规则，无需再加另一套安装器。

```bash
# 新设备的部署步骤。已有任务先停止，再处理设备权限。
sudo install -m 644 deploy/k1/udev/*.rules /etc/udev/rules.d/
sudo udevadm control --reload-rules
sudo udevadm trigger
sudo usermod -aG dialout,audio,video "$USER"
# 重新登录后检查；无需打开设备。
ls -l /dev/tcm
id -nG
```

## 语音模块内部与主机模块

主机侧串口协议、唤醒配置下发、SenseVoice/VAD 接入和原音色提示音已交付。内部 `/data/build/demo_vtn`、watcher、唤醒资源属于语音模块的厂商预装系统，不是 K1 上再装的通用 USB 驱动。目前未取得该内部程序源码，不能把已有主机代码等同于已开源内部固件。

`configs/device/voice/m260c-module-reference.json` 记录此前保存的参数供对照，不自动应用。`common.debug=0` 对应关闭连续调试录音，避免此前的模块存储占满；增益和 beam 参数只作为本机历史参考，不应给不同批次模块盲目覆盖。本次未读取实时模块内部配置，也未执行 ADB 恢复。

`deploy/k1/recover_voice_module.py` 的可选恢复使用系统 `adb`。本机这次核查没有系统级 `adb`，软件源有 riscv64 候选 `1:34.0.4-1build3`；此前诊断使用的是私有目录解包版本。复现时如要使用可选恢复，应安装系统 `adb`/`acl`，按原指南授权调试接口；正常 USB 音频/串口不需要 ADB。此项不要求发布临时诊断程序或内部固件。

## 深度流限制

K1 已有 riscv64 OpenNI2 2.2.0.33 框架和头文件，安装目录可见 DummyDevice、OniFile、PS1080、PSLink，未见 `liborbbec`。当前深度 USB 节点已有 `video` 组权限；旧文档中“规则未安装/只读权限”只代表当时状态，不代表此次实机状态。

可选深度接口代码能编译，不代表实际 Astra Pro 毫米深度流能采集。厂家材料里的其他架构库不能直接用于 riscv64。本次不启用深度服务，也不声称已解决这一驱动缺口；需要真实兼容驱动和帧验证后再交付为可用能力。

## 复现核对与工程规范

驱动代码继续放在所属 ROS2/SDK 模块，固件放 `robot/firmware`，权限规则放 `deploy/k1/udev`，设备参数放 `configs/device`，版本和来源放 `deploy/k1/snapshot`。不创建混杂源码、二进制和测试日志的大 `drivers` 目录。

`scripts/check_delivery.py`、资源导入及原生/ROS2 编译步骤仍按复现指南执行。现场插拔、采集、完整巡检是独立验收，不能以文件齐全代替。评分图中的时延、准确率、硬件利用率也需要对应实测数据，驱动文件齐全本身不构成性能达标证据。
